Version 1.0

# Purpose

This document defines the physical architecture of the SYNAPSE universe.

While previous documents describe the story, interactions, and behavior, this document describes how the world itself is constructed inside the rendering engine.

Every visual element, district, particle, shader, and interaction exists within this architecture.

The objective is to create a scalable, maintainable, high-performance world capable of growing for years without architectural redesign.

---

# Core Philosophy

SYNAPSE is one world.

Not many scenes.

The universe never unloads conceptually.

Only its representation changes.

The visitor should always feel they exist inside one continuous reality.

---

# Engine Philosophy

The renderer is not responsible for storytelling.

The renderer is responsible only for displaying the world.

Storytelling belongs to the Experience Engine.

The renderer simply executes.

# World Rules

Nothing owns the universe.

The universe owns everything.

Every object must belong to exactly one district.

No orphan objects.

No floating global meshes.

---

# Scene Graph Philosophy

Every object exists inside a predictable hierarchy.

Example

```text
District

↓

Project

↓

Artifact

↓

Components

↓

Interactive Elements

↓

Effects
```

Every node has exactly one parent.

Cycles are forbidden.

# District Manager

Responsibilities

Unload inactive districts.

Maintain district state.

Coordinate streaming.

Preserve continuity.

Provide navigation targets.

# GLTF Strategy

Each major artifact is its own GLTF.

Avoid monolithic scenes.

Example

Good

```text
fuze-phone.glb

fuze-dashboard.glb

fuze-ai.glb
```

Bad

```text
entire-fuze-world.glb
```

Smaller assets stream more efficiently.

---

# Instancing Strategy

Repeated geometry must use GPU instancing.

Examples

Trees

Particles

Stars

Constellations

Energy nodes

Crystals

Never duplicate meshes unnecessarily.

---

# Level of Detail (LOD)

Every major object supports multiple levels.

Near

Highest detail.

Medium

Reduced geometry.

Far

Simplified silhouette.

Very Far

Billboard or particle representation.

LOD transitions must be seamless.

---

# Frustum Culling

Invisible objects should not render.

District Manager supplies visibility hints.

Objects outside view are suspended where possible.

---

# Occlusion Strategy

Large districts should hide unnecessary geometry behind environmental structures.

Avoid rendering unseen complexity.

---

# Streaming

Assets load progressively.

Priority

Current district

↓

Adjacent district

↓

Likely next district

↓

Background districts

Streaming should always stay ahead of the visitor.

---

# Lighting Groups

Each district owns its lighting profile.

Global lighting exists only for continuity.

Local lighting defines emotion.

Lighting transitions interpolate smoothly.

---

# Reflection System

Only premium objects receive reflections.

Reflection indicates significance.

Avoid reflecting everything.

---

# Shader Ownership

Materials never own shaders directly.

Shaders belong to the Shader System.

Materials reference shader presets.

This ensures consistency across the universe.

---

# Particle Ownership

Particles never belong directly to projects.

They belong to the Particle Engine.

Projects request particle behaviors.

The engine executes them.

---

# Animation Ownership

Meshes never animate themselves.

Animations are requested through the Animation System.

This avoids conflicting timelines.

---
