# Purpose

This document defines the complete engineering architecture of SYNAPSE.

The goal is not simply to build a portfolio.

The goal is to build a reusable Interactive Experience Engine capable of powering future interactive websites, storytelling experiences, and digital products.

SYNAPSE is therefore engineered as a platform rather than a one-off application.

---

# Engineering Philosophy

The architecture must prioritize:

* Scalability
* Reusability
* Predictability
* Performance
* Maintainability
* Extensibility
* Readability
* Developer Experience

Every system should solve one responsibility exceptionally well.

---

# Core Engineering Principles

## Principle 1

Experience over Pages

There are no pages.

Everything exists inside one continuous runtime.

Routing is secondary.

Experience is primary.

---

## Principle 2

Composition over Inheritance

Every system should be assembled from reusable components.

Never create monolithic classes.

---

## Principle 3

Data Drives Everything

Scenes are configuration.

Animations are timelines.

Camera paths are data.

Interactions are state.

Avoid hardcoded behaviors.

---

## Principle 4

Every System Owns One Responsibility

Example

Camera System

↓

Only camera.

Particle Engine

↓

Only particles.

Lighting Engine

↓

Only lighting.

Never mix concerns.

# Monorepo Structure

The project is structured as a Turborepo.

```text
apps/

    portfolio/

packages/

    engine/

    world/

    renderer/

    animation/

    camera/

    interactions/

    ai/

    ui/

    shaders/

    particles/

    assets/

    config/

    hooks/

    utils/

    types/

docs/
```

Each package has one responsibility.

No package should depend on unrelated systems.

The runtime follows this order.

Boot

↓

Initialize Engine

↓

Load Config

↓

Detect Device Capability

↓

Load Essential Assets

↓

Initialize Renderer

↓

Initialize World

↓

Initialize Timeline

↓

Enable Interaction

↓

This sequence is mandatory.

# Dependency Rules

Allowed

UI

↓

Engine

↓

Renderer

↓

ThreeJS

---

Forbidden

Renderer importing UI

Animation importing AI

Camera importing World

Particles importing Timeline

Cross-dependencies are prohibited.

Communication occurs through events.

---

# Rendering Strategy

The renderer owns:

Canvas

Lighting

Environment

Post Processing

Shadow Maps

Render Loop

No feature outside the renderer may directly manipulate WebGL.

---

# Scene Architecture

Every scene is self-contained.

Each scene exposes:

Initialize()

Mount()

Enter()

Update()

Exit()

Dispose()

The Experience Engine controls when these lifecycle methods execute.

---

# State Management

Global State

Experience progress

AI state

Theme

Accessibility

Performance

Scene

Current interaction

Camera mode

Asset status

Everything else should remain local.

Avoid unnecessary global state.

---

# Asset Strategy

Assets are divided into:

Essential

High Priority

Medium Priority

Background

Experimental

Only Essential assets block startup.

Everything else streams progressively.

---

# Animation Strategy

No animation begins automatically.

All animations respond to:

Timeline

Interaction

Events

AI commands

Performance mode

Animations must be deterministic.

---

# Camera Ownership

Only one object owns the camera.

The Camera Controller.

Scenes request movement.

They never manipulate transforms.

---

# AI Architecture

AI exists as a service.

The renderer never communicates directly with AI.

Instead:

AI

↓

Event

↓

Experience Engine

↓

Camera

↓

Scene

↓

UI

Loose coupling is mandatory.

---

# Event System

All communication occurs through events.

Examples

SceneEntered

ProjectFocused

TimelineUpdated

ConversationStarted

PerformanceChanged

LoadingCompleted

Events must be typed.

No string literals.

---

# Error Handling

Rendering failure

↓

Fallback renderer

Asset failure

↓

Placeholder geometry

AI failure

↓

Graceful fallback UI

Animation failure

↓

Skip timeline segment

The experience must continue.

# Performance Budget

Target FPS

60

Maximum Draw Calls

< 250

Maximum Active Lights

6

Maximum Post Processing Passes

5

Largest Initial Bundle

< 350 KB (excluding streamed assets)

Largest GLB

Optimized and compressed.

All textures:

KTX2.

Geometry:

Draco.

Instancing whenever possible.

# Definition of Done

A feature is complete only when:

* Meets the design specification.
* Meets performance budget.
* Supports forward and reverse timeline.
* Includes documentation.
* Has tests.
* Supports accessibility.
* Produces no console warnings.
* Integrates cleanly with the Experience Engine.
* Does not reduce frame rate below target.
* Feels invisible to the visitor.

# Final Statement

SYNAPSE is engineered like a modern game engine disguised as a portfolio.

The architecture exists to ensure that creativity is never constrained by technical debt.
