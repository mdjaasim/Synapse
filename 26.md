# PROJECT SYNAPSE

# Document 25 — GSAP Animation Engine & Timeline Architecture

Version 1.0

---

# Purpose

This document defines the animation architecture of SYNAPSE.

Animations are not created inside React components.

Animations are not manually triggered from UI.

Animations are registered, orchestrated, synchronized, and controlled by a centralized Animation Engine.

The objective is to make every animation reusable, reversible, synchronized, and maintainable.

---

# Core Philosophy

Components do not animate.

The Animation Engine animates components.

Animation is a service.

Not component logic.

---


# Common Failure Modes

Avoid

Creating GSAP timelines inside React components.

Multiple timelines controlling the same property.

Hardcoded durations.

Independent animation loops.

Restarting timelines unnecessarily.

Unmanaged cleanup.

Ignoring reverse playback.

Animation ownership conflicts.

Frame-dependent logic.

# Definition of Done

The Animation Engine is complete when:

Every animation in SYNAPSE is registered.

Every timeline is reusable.

Scroll progress controls narrative deterministically.

Camera, lighting, particles, and shaders synchronize seamlessly.

No animation logic exists inside presentation components.

Cursor can add a new animation without modifying existing architecture.
