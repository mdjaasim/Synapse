# PROJECT SYNAPSE

# Document 06 — Scroll Engine & Timeline System

Version 1.0

---

# Purpose

The Scroll Engine is the primary interaction mechanism of SYNAPSE.

Unlike traditional websites where scrolling moves the page, SYNAPSE interprets scrolling as a manipulation of time.

The engine transforms physical scroll input into a deterministic cinematic timeline that drives every animation, camera movement, interaction, and environmental change.

The visitor never scrolls through content.

The visitor scrubs through a living story.

---

# Design Philosophy

Scrolling is not navigation.

Scrolling is storytelling.

The user's scroll wheel acts as the playback control of an interactive film.

Every movement must feel intentional, smooth, reversible, and physically believable.

---

# Core Responsibilities

The Scroll Engine is responsible for:

* Reading raw scroll input
* Normalizing scroll values
* Managing timeline progression
* Synchronizing scenes
* Driving animations
* Coordinating camera motion
* Triggering interactions
* Predictive asset loading
* Reverse playback
* Scroll inertia
* Device consistency


# Timeline Philosophy

The timeline represents the complete experience.

```text
0.000

↓

Beginning

↓

Middle

↓

Ending

↓

1.000
```

Everything references timeline progress.

Never pixel positions.

Never browser scroll values.

# Scroll Velocity

Velocity is treated as an expressive input.

Slow scrolling

↓

Longer anticipation

↓

Smoother transitions

Fast scrolling

↓

Accelerated timeline

↓

Preserved continuity

Velocity should influence pacing—not break animation quality.

---

# Scroll Damping

Immediate response feels robotic.

Excessive damping feels sluggish.

The engine must balance:

Responsiveness

↓

Momentum

↓

Elegance

The world should feel like it has physical mass.

---

# Reverse Scroll

Reverse scrolling is a first-class feature.

Every interaction must support rewinding.

Examples

Project assembly

↓

Project disassembly

Camera push

↓

Camera pull

Particle formation

↓

Particle dispersion

Nothing should "reset."

Everything should evolve backwards naturally.

# Scroll Locking

The engine may temporarily reduce scroll responsiveness only during:

Critical cinematic reveals

Major world transformations

First-time onboarding

This should never exceed a few seconds and must always remain reversible.

# Predictive Loading

The Scroll Engine predicts likely future scenes.

Assets for the next segment begin loading before they are needed.

Users should never encounter loading interruptions during scrolling.

---

# Performance Adaptation

If FPS drops below target:

Reduce particle density

Simplify shader complexity

Reduce distant animation updates

Preserve timeline consistency

Never reduce interaction quality.

---

# Accessibility

Provide an alternative mode where:

Animations are simplified

Scroll sensitivity is reduced

Motion intensity is minimized

Timeline progression remains intact

The story should remain fully understandable.

# Cursor Implementation Strategy

Cursor must implement the Scroll Engine before creating any visual scenes.

Recommended order:

1. Configure Lenis.
2. Build normalized timeline.
3. Create timeline manager.
4. Connect timeline to camera.
5. Connect timeline to placeholder animations.
6. Validate reverse playback.
7. Add scene transitions.
8. Integrate with Experience Engine.
9. Expose debug overlay.
10. Optimize.

No production visuals should be added until the timeline system is stable.

---

# Common Failure Modes

Avoid:

* Using browser scroll position directly.
* Hardcoding pixel-based animation triggers.
* Camera transforms tied directly to wheel events.
* Independent animation timelines fighting each other.
* Scroll snapping.
* Multiple systems owning timeline state.
* Frame-dependent animation progression.
* Non-reversible animations.

---

# Engineering Review Checklist

Before approving the Scroll Engine, verify:

✔ Timeline is normalized.

✔ Reverse scrolling works perfectly.

✔ Camera movement is deterministic.

✔ Scene transitions overlap smoothly.

✔ Scroll velocity enhances—not disrupts—the experience.

✔ Performance remains stable at target FPS.

✔ No visual popping during transitions.

✔ Timeline state survives refresh (where appropriate).

✔ Debug tools expose current timeline state.

✔ Every animation derives from the same timeline source.

---

# Final Statement

The Scroll Engine is not an input handler.

It is the heartbeat of SYNAPSE.

Every animation, every camera movement, every transformation, and every emotional beat is synchronized through this single continuous timeline.

The visitor should never feel they are scrolling a webpage.

They should feel they are directing a cinematic experience with effortless precision.
