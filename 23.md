# Document 22 — React Component Architecture & Application Structure

Version 1.0

---

# Purpose

This document defines the React architecture that powers SYNAPSE.

The goal is not simply to organize components.

The goal is to build an architecture that scales as the experience grows while remaining predictable, reusable, performant, and easy to understand.

Every component should have one responsibility.

Every responsibility should have one owner.

---

# Core Philosophy

React manages the application.

The Experience Engine manages the universe.

Three.js renders the universe.

GSAP animates the universe.

The AI understands the universe.

No system should perform another system's responsibility.

# Component Rules

Every component must:

Have one responsibility.

Be reusable.

Be typed.

Be documented.

Support accessibility.

Avoid side effects.

Remain testable.

---

# Rendering Rules

Never create Three.js objects directly inside UI components.

Rendering belongs inside World components.

UI components never manipulate meshes.

# Definition of Done

The React architecture is complete when:

The application shell never remounts.

Every component has one clear responsibility.

The world and UI remain completely decoupled.

Adding a new district requires minimal engineering effort.

Cursor can navigate the codebase without ambiguity.

The architecture remains understandable by a new engineer within one hour.

---

# Final Statement

The React architecture is the skeleton of SYNAPSE.

If the Experience Engine is the brain and the World Engine is the body, React provides the structure that keeps every system organized.

The codebase should feel as elegant and intentional as the experience it creates.
